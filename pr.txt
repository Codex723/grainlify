Title: Add admin authorization guard to init_threshold_monitoring
Branch: fix/threshold-monitoring-auth
Base branch: master
Commit(s): a1ea9dde, be35a2bc

================================================================================
SUMMARY
================================================================================

This PR adds admin-only authorization to the `init_threshold_monitoring`
entrypoint so that unauthorized callers are refused with
`ContractError::Unauthorized`, while authorized admin calls proceed unchanged.
Corresponding unit tests cover the refusal path, the success path, and a
state-mutation safety check.

The authorization pattern mirrors `update_rate_limit_config`: fetch the
`Address` stored under `DataKey::Admin` from instance storage, then call
`Address::require_auth()`.

================================================================================
PROBLEM
================================================================================

`init_threshold_monitoring` previously had no authorization guard. Any caller
could initialize threshold-based circuit breaking, a sensitive operator action
that should be restricted to the contract admin.

================================================================================
CHANGES
================================================================================

### 1. contracts/program-escrow/src/lib.rs

#### a) Module wiring
Added `#[cfg(test)] mod test_threshold_monitor;` so the new authorization
tests compile and run under `cargo test`. Placed after `mod threshold_monitor;`,
before the pre-existing broken `#[cfg(any())] mod threshold_monitor_prop_tests;`.

#### b) Authorization guard in `init_threshold_monitoring`
Added doc comment and guard at the top of the function:

```rust
    /// # Authorization
    ///
    /// Only the contract admin may call this entrypoint.
    pub fn init_threshold_monitoring(env: Env) {
        // Only admin can initialize threshold monitoring
        let admin: Address = env
            .storage()
            .instance()
            .get(&DataKey::Admin)
            .unwrap_or_else(|| panic_with_error!(&env, &ContractError::ProgramInitFailed));
        admin.require_auth();

        threshold_monitor::init_threshold_monitor(&env);
    }
```

Behavior:
- Reads the `Address` under `DataKey::Admin` from instance storage.
- If no admin is set, panics with `ContractError::ProgramInitFailed`.
- Calls `admin.require_auth()` — only the admin can proceed.
- On success, calls `threshold_monitor::init_threshold_monitor(&env)` unchanged.

Error variant: `ContractError::Unauthorized` (raised by Soroban's
`Address::require_auth()` when the caller does not match).

### 2. contracts/program-escrow/src/entrypoints/pause_and_limits.rs

Mirrored the identical authorization guard in the duplicate/dead file copy
for consistency, even though it is not part of the active build path.

### 3. contracts/program-escrow/src/test_threshold_monitor.rs

Added `env.mock_all_auths();` to `setup_test()` so tests without explicit auth
mocks still pass.

Added three new tests:

#### Test 1: `test_unauthorised_cannot_init_threshold_monitoring`
- `#[should_panic(expected = "Unauthorized")]`
- Initializes contract with an admin, then calls `init_threshold_monitoring()`
  while mocking only a non-admin address. `require_auth()` fails and panics.

#### Test 2: `test_admin_can_init_threshold_monitoring`
- Initializes contract with an admin, calls `init_threshold_monitoring()`
  while mocking the admin address. `require_auth()` passes and default config
  is set. Verifies `failure_rate_threshold() == 10`,
  `time_window_secs() == 600`, `cooldown_period_secs() == 300`.

#### Test 3: `test_no_state_mutation_after_refused_init_threshold_monitoring`
- Confirms threshold config key does not exist before init.
- Attempts unauthorized init (wrapped in `catch_unwind`), asserts it panics.
- Confirms config key still does not exist — no state was mutated.
